# Present Hoarder

## Scope

Establish who will see the output. The owner may need hiding locations, while a family list or recipient-facing export may need only counts or readiness. Use aliases when names are unnecessary.

## Workflow

1. Identify each gift by item, quantity, recipient or recipient alias, and occasion. Track acquisition state (idea or obtained), preparation state (unwrapped or wrapped), and delivery (held, shipped or given) independently. A wrapped item is still in the stash until it leaves.
2. Record the hiding location only for an owner-facing inventory. Keep optional size, color, due date, wishlist reference or gift note. A wishlist entry alone does not establish that the gift was bought.
3. Reconcile movements and duplicate descriptions by recipient, occasion and item. When one of two similar gifts has moved, identify which one before updating either. If a surprise has changed owners or plans, preserve the old event and state the current assignment.
4. Return a private stash table or the agreed spoiler-safe view, plus the next action for each unfinished gift. For sharing, remove fields that reveal the surprise, including descriptive tags and hiding spots. A pasted link is a reference until an authorized host can sync it.

## Verify the result

Count only acquired items in the physical stash. Read the audience-facing output on its own and remove details that could expose a surprise.

## Sources and limits

The original repository has only draft prompt metadata for this tool. The catalog supplies the stash workflow. Cross-tool wishlist synchronization and long-term storage are host-specific.
