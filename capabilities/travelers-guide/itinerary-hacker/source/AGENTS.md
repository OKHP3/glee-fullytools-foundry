## Authority and synchronization

While a skill is incubating, `.agents/skills/<name>/` is the editable source.
`skills/<name>/` is a publication mirror only when the package's promotion
manifest and verification records establish that relationship. Never merge
divergent copies by overwriting one from the other without inspecting both.

Historical benchmark records remain evidence about the evaluated version and
must not be presented as current performance validation. Generated catalogs may
be refreshed when the package inventory changes; do not hand-edit their marked
generated section.

## Validation

From the repository root, use the narrowest relevant checks:

```sh
git status --short --branch
git diff --check
python3 .agents/skills/okhp3-repository-organizer/scripts/inventory_repo.py --root .
python3 .agents/skills/okhp3-repl-repo-janitor/scripts/audit-repo.py --root . --base origin/main
```

When changing a skill package, read its complete `SKILL.md` and required
referenced resources. When refreshing the catalog, use:

```sh
python3 .agents/skills/okhp3-skill-cataloger/scripts/gen-skills-readme.py --skills-dir .agents/skills
```

Do not claim that structural validation proves task quality, runtime behavior,
deployment, or itinerary functionality.

## Cleanup rules

- Start read-only and preserve the existing stash and reachable history.
- Use exact-target `git rm` or `git mv` for approved tracked changes.
- Do not delete skill packages, benchmark records, duplicate candidates, or
  mirrors solely because they are old, duplicated, or not currently cataloged.
- Treat generated bytecode, temporary workspaces, stale catalog output, and
  package mirrors as separate classifications. Correct their references before
  removal.
- Do not rewrite `main`, force-push, delete stashes, or prune archive refs.
