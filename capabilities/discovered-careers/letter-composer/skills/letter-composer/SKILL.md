# Letter Composer

## Scope

Ask for the role, posting or role summary, truthful experience examples and any tone or length constraints. If the person supplies a draft, preserve their voice and any passages they ask to keep. When the organization or hiring contact is unknown, use an appropriate general greeting.

## Workflow

1. Pick one or two real needs from the posting. For each, select an example showing what the person did, why it mattered and the documented result. Keep the difference between an individual contribution and a team's outcome visible.
2. Open by naming the role and a specific reason for interest grounded in supplied material. Build the body around the examples. Close with a concise statement of interest and a practical next step. Avoid invented company news, personal connections and generic superlatives.
3. Edit for requested tone, length and plain reading order. Read the letter on its own and compare names, facts and metrics with the evidence. Keep questions or factual caveats outside the copyable letter.
4. If a posting is missing, deliver a clearly labeled general-interest draft or ask for a short role description. If an example is missing, provide a fill-in line and explain what evidence belongs there. Return text ready for the person's review and submission.

## Draft from an evidence card

Select the strongest overlap between one advertised duty and something the applicant actually did. Use the four fields in `references/cover-letter-evidence-card.md` when the worksheet is available. Distinguish what the applicant personally did from the outcome reported for the group. When the result is unknown, a precise description of the action is enough. A draft can use one strong incident instead of trying to cover every duty.

Produce the letter now when there is enough evidence. Give it a greeting, an opening that names the target, a body that shows how the example fits, and a concise close. A short note for an application field can omit greeting and signature when requested. For a missing recipient name, use “Dear Hiring Team” or the supplied team name. Never guess a person's name. Omit unused address lines and contact fields from copy-ready text.

When the applicant has supplied no signature, finish the letter at the closing phrase, such as “Warm regards,”. Add a name only if the applicant supplied it. Before returning the letter, scan the copy for bracketed prompts, blank signature lines and template fields and remove them. If the user explicitly requests a fill-in template, label that output as a template.

## Revise the letter

Apply a corrected fact throughout the copy, including any supporting card. Preserve an approved sentence exactly if requested. When shortening, cut generic interest statements or repeated claims first. Keep the applicant's best example and a clear link to the role. Count the portion the user specified. If a firm word limit has an ambiguous scope, keep the entire letter including greeting and sign-off within the cap.

For a word cap, leave a margin and focus the answer on the finished letter. Report a numerical word count only after verifying the final copy with a reliable counter using the user's counting rule. For whitespace-delimited words, count the nonempty tokens in the exact greeting, body and sign-off after the last edit. When that verification is unavailable, omit the numerical self-report.

Return the complete revised letter in the requested form so the user can copy it without reconstructing a patch. A source note or evidence card belongs after the letter if requested. For plain text, provide the actual text. If the user requests DOCX or PDF, use an available file exporter and verify the result before offering a download. With no exporter, provide the complete plain text and identify the requested file type as pending.

## Verify the result

Check the letter against the applicant’s source facts and the exact wording of any length or tone constraint. Read the copyable letter without its notes to catch accidental placeholders.
