## Change conventions

- Keep each skill directory name, `SKILL.md` `name`, and referenced paths in
  agreement.
- Preserve required ecosystem names such as `SKILL.md`, `README.md`,
  `LICENSE.md`, `MANIFEST.md`, and `openai.yaml`.
- Use portable lowercase kebab-case for new ordinary names, with documented
  exceptions for tool-required or package-required names.
- Keep generated catalog sections generated by the cataloger. Do not hand-edit
  them.
- Keep skill instructions factual, operational, and progressively disclosed.
- Do not commit secrets, credentials, private Notion URLs, or confidential
  material.
- Do not use em dashes in generated content.
- Preserve historical evaluation records, but label them historical or
  analytical when they do not evaluate the current package version.

## Safe change workflow

1. Confirm that the change belongs to this repository and identify its owning
   skill or generated surface.
2. Read the owning `SKILL.md` and directly referenced resources before editing.
3. Start read-only and inspect Git status, history, references, and mirrors.
4. Preserve neutral and branded variants until canonical ownership is recorded.
5. Use `git mv` for approved tracked moves and never overwrite a collision.
6. Regenerate catalogs with the documented tool rather than editing generated
   sections manually.
7. Run `git diff --check`, the catalog check, relevant package validation, and
   the repository audit after changes.
8. Report confirmed facts, inferences, unknowns, changed files, and remaining
   decisions separately.
