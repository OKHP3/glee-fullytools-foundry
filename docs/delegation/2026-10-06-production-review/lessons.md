# Retry corrections and reusable closeout method

These corrections come from the October 5 preflight, the protected-main
heading publication and the October 6 portable-foundation release. They are
operational learning records, not canonical clauses or an autonomous update policy.

| Observed cause | Correction applied | Evidence and boundary |
| --- | --- | --- |
| The first request linked methods from another product while the checkout was FoundRy. Controlling requirements and destinations were unclear. | Use the owner's replacement root guide and current portable-capability/product contracts as the controlling foundation requirements. Preserve the earlier handoff and identify a separately supplied PRD as unavailable. | Frozen source `de092dbc`; `AGENTS.md`, `portable-capabilities.md` and `products/README.md`. No MurderBird product material imported. |
| Small worker goal budgets were exhausted by instruction/context overhead before useful inspection. | Use the owner's permitted task ceiling, request an actual goal counter, retain failed identities in accounting and reserve closure capacity. Reuse reports before dispatching new work. | Original private ledger retains both retired attempts; fresh review duties remain bounded. Goal meters do not establish total provider billing. |
| Repeated Replit app-connector authentication calls produced no workspace evidence. | Stop unchanged retries, inspect the existing authorized browser session and record source parity separately from app-connector and Git-provider authentication. | Direct source inspection found the foundation SHA on Replit. Both app connections still return `UNAUTHORIZED`; no new OAuth scope granted. |
| A direct main push was rejected by repository protection. | Use normal feature branches, required PR checks and an expected-head protected merge. Preserve history and prove local/remote parity afterward. | [PR #24](https://github.com/OKHP3/glee-fullytools-foundry/pull/24) and [PR #25](https://github.com/OKHP3/glee-fullytools-foundry/pull/25). No protection bypass or force push. |
| The earlier heading commit did not publish the separate portable-capability work. | Inspect current PRs, source history and attributable host receipts instead of assuming one thread owns every improvement. Reuse the later merged foundation evidence. | PR #25 integrated 23 files; the heading is only a placeholder. Unrelated Replit branches retain their own ownership. |
| Local host/tool assumptions caused runner and Windows encoding failures. | Use declared/bundled prerequisites, report real skips and distinguish environment repair from source repair. Quote Git revision expressions in PowerShell. | The foundation integration records a corrected UTF-8 regression run; seven portable regressions passed again during this review. |
| Old handoff statements became stale as later source and host receipts arrived. | Add dated addenda and new evidence; preserve the original failure record. Record exact source/tree identity and expire only affected checks. | The October 5 private handoff remains intact; this package records the later foundation and review. |
| Review agreement could be mistaken for actual migrated-product or native-host success. | Separate analytical review from observed application tests, native-host runs and protected holdouts. Require exact artifact evidence for each future compatibility claim. | Independent role prompts share a model/source family; product conversions, native adapters and holdouts remain unrun. |
| A prompt formatter accepted arbitrary nonempty gate strings. | Include receipt references and require independent inspection before action. Make P15's separate owner-request condition explicit. | The disruptor reproduced the conditional weakness with synthetic receipts; the corrected helper rejects the obsolete P15 gate and never launches a worker. Receipt presence does not prove truth or authority. |

For the next retry, inspect the current source and ownership, preserve existing
work, freeze the decision and evidence, perform the smallest decisive checks,
review findings, publish the authorized result, verify each receiving surface,
then append the learning and close the bounded assignment. A new fact can reopen
an affected claim; unchanged failures do not justify an indefinite retry loop.
